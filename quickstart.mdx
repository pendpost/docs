---
title: Quickstart
description: Boot pendpost in under a minute via git, npx, or docker, then open the dashboard or drive it over MCP.
---

pendpost runs as a single local process. It runs live by default: a lane with no credentials is live-but-unauthenticated and waits for you to connect it, so nothing publishes until you do. To walk the whole loop risk-free first, start it in mock mode with `PENDPOST_MODE=mock`. Pick whichever path fits your workflow.

## Install and run

<Tabs>
  <Tab title="git">
    Clone the repository and enter it:

    ```bash
    git clone https://github.com/pendpost/pendpost.git
    cd pendpost
    ```

    The server has zero runtime dependencies, so no root install is needed. Just start it. This builds the dashboard on first run, then boots:

    ```bash
    npm start
    ```

    Or run the binary directly. This is equivalent, the same build-on-first-run entry point:

    ```bash
    node bin/pendpost.mjs
    ```

    Then open:

    ```
    http://127.0.0.1:8090
    ```
  </Tab>
  <Tab title="npx">
    A single command boots the server and builds the dashboard on first run:

    ```bash
    npx pendpost
    ```

    When it is up, open the dashboard:

    ```
    http://127.0.0.1:8090
    ```
  </Tab>
  <Tab title="docker">
    ```bash
    docker compose up
    ```

    The host exposure stays loopback-only. When the container is up, open:

    ```
    http://127.0.0.1:8090
    ```
  </Tab>
</Tabs>

## First run

Start it with `PENDPOST_MODE=mock` and every platform lane runs through the credential-free mock driver: no real API calls. Mock mode runs in a private demo workspace in your temp folder, which opens on an example `Acme Launch` campaign so the dashboard shows real content instead of an empty screen. Without `PENDPOST_MODE=mock`, pendpost is live, so an unconnected lane waits for its credential rather than publishing. On pendpost 2.8.0 and earlier, also set `PENDPOST_ROOT=/tmp/pendpost-demo` for mock mode (see [Mock mode](/mock-mode)).

From the dashboard you can walk the full loop: draft a post, approve it, schedule it, watch it publish through the mock driver, and read back fabricated insights. See [Mock mode](/mock-mode) for the complete walkthrough.

Mock runs do not exercise rate limits, native scheduling, or the Meta 368 breaker; those engage only on a live lane. See [Mock mode](/mock-mode) for what mock does and does not cover.

## Drive it headless

The same `npx pendpost` (or `npm start`) boot also exposes the MCP server, so an agent can run onboarding without the dashboard. Connect an MCP client, call `pendpost_health` to confirm readiness, then `plan_list` to read the workspace (a fresh install shows the example Acme Launch campaign), then `campaign_create` to start your own. See [MCP](/mcp-server) to connect a client.

<Note>
pendpost binds `127.0.0.1` (loopback) by default. The docker image binds `0.0.0.0` inside the container, but docker compose still maps the port to loopback on your host only.
</Note>

## Going live later

When you are ready to publish for real, add credentials for the platforms you use in your own `.env`. Every lane is already live; adding a credential is what lets that lane actually publish instead of waiting unauthenticated. (A lane only runs through the mock driver when you set `PENDPOST_MODE=mock`.) See:
